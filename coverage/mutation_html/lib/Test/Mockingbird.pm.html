  148: =head1 LIMITATIONS
  149: 
  150: =over 4
  151: 
  152: =item Call-through to an inherited method does not consult C<AUTOLOAD>
  153: 
  154: When C<spy()>, C<before()>, C<after()>, C<around()> or C<async_spy()> wrap a
  155: method the package does not declare itself, they call through to the first
  156: implementation found in the package's parent classes (looked up at call
  157: time, so a later mock of the parent is seen). If there is none they die with
  158: C<"Undefined subroutine">; an C<AUTOLOAD> is not tried.
  159: 
  160: =item Prototype mismatch warning from C<spy()>
  161: 
  162: C<spy()> installs its wrapper directly without going through C<mock()>,
  163: so C<Scalar::Util::set_prototype> is not applied. Wrapping a prototyped
  164: function with C<spy()> still emits a C<Prototype mismatch> warning. Use
  165: C<mock()> with a delegating wrapper if warning-free wrapping is required.
  166: 
  167: =item No nested deep_mock scopes
  168: 
  169: L<Test::Mockingbird::DeepMock> calls C<restore_all()> at scope exit, which
  170: removes every active mock. Nested C<deep_mock> blocks cause the inner exit
  171: to also tear down the outer mocks. Do not nest C<deep_mock> calls.
  172: 
  173: =item Thread safety
  174: 
  175: The internal state (C<%mocked>, C<%mock_meta>, C<@call_log>) is per-process
  176: lexical state. Concurrent threads that install and restore mocks will race.
  177: Do not use this module in threaded test harnesses without external locking.
  178: 
  179: =item Spy return value is a flat list
  180: 
  181: C<spy()> and C<async_spy()> return a coderef that yields a flat list of
  182: call records. A future version may return an arrayref to reduce stack
  183: pressure; the API is not yet changed to avoid breaking callers.
  184: 
  185: =item Private-function encapsulation
  186: 
  187: Functions prefixed with C<_> are private by convention but are not enforced
  188: at runtime (C<Sub::Private> is not activated). White-box tests in C<t/unit.t>
  189: call private functions directly. If C<Sub::Private> enforcement is added, a
  190: testing-interface export mechanism will be required.
