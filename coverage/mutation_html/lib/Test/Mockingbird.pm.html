  200: =head1 DESCRIPTION
  201: 
  202: Test::Mockingbird provides mocking, spying, dependency injection,
  203: call-order verification, and constructor interception for Perl test suites.
  204: 
  205: =head1 DIAGNOSTICS
  206: 
  207: L</diagnose_mocks> returns a structured hashref of all active mock layers;
  208: L</diagnose_mocks_pretty> returns the same as a human-readable multi-line
  209: string.
  210: 
  211: Each installed layer records:
  212: 
  213:   type          -- category (mock, spy, inject, mock_return, ...)
  214:   installed_at  -- file and line number of the outermost user call site
  215: 
  216: =head1 LIMITATIONS
  217: 
  218: =over 4
  219: 
  220: =item A misspelled method name is mocked without complaint
  221: 
  222: C<mock 'My::Module::fecth' =E<gt> sub { ... }> installs a new sub called
  223: C<fecth>; the real C<fetch> is left untouched and a test relying on the mock
  224: may pass for the wrong reason.  Check with C<can> (or C<diagnose_mocks()>)
  225: when a mock seems to have no effect.
  226: 
  227: =item Names with non-ASCII characters
  228: 
  229: Package and method names are used as given, so any name Perl accepts under
  230: C<use utf8> (e.g. C<CafÃ©::prix>) can be mocked, spied on, injected and
  231: restored.  C<mock_core()> only accepts ASCII builtin names, which covers
  232: every Perl builtin.
  233: 
  234: =item Call-through to an inherited method does not consult C<AUTOLOAD>
  235: 
  236: When C<spy()>, C<before()>, C<after()>, C<around()> or C<async_spy()> wrap a
  237: method the package does not declare itself, they call through to the first
  238: implementation found in the package's parent classes (looked up at call
  239: time, so a later mock of the parent is seen). If there is none they die with
  240: C<"Undefined subroutine">; an C<AUTOLOAD> is not tried.
  241: 
  242: =item Prototype mismatch warning from C<spy()>
  243: 
  244: C<spy()> installs its wrapper directly without going through C<mock()>,
  245: so C<Scalar::Util::set_prototype> is not applied. Wrapping a prototyped
  246: function with C<spy()> still emits a C<Prototype mismatch> warning. Use
  247: C<mock()> with a delegating wrapper if warning-free wrapping is required.
  248: 
  249: =item No nested deep_mock scopes
  250: 
  251: L<Test::Mockingbird::DeepMock> calls C<restore_all()> at scope exit, which
  252: removes every active mock. Nested C<deep_mock> blocks cause the inner exit
  253: to also tear down the outer mocks. Do not nest C<deep_mock> calls.
  254: 
  255: =item Thread safety
  256: 
  257: The internal state (C<%mocked>, C<%mock_meta>, C<@call_log>) is per-process
  258: lexical state. Concurrent threads that install and restore mocks will race.
  259: Do not use this module in threaded test harnesses without external locking.
  260: 
  261: =item Spy return value is a flat list
  262: 
  263: C<spy()> and C<async_spy()> return a coderef that yields a flat list of
  264: call records. A future version may return an arrayref to reduce stack
  265: pressure; the API is not yet changed to avoid breaking callers.
  266: 
  267: =item Private-function encapsulation
  268: 
  269: Functions prefixed with C<_> are private by convention but are not enforced
  270: at runtime (C<Sub::Private> is not activated). White-box tests in C<t/unit.t>
  271: call private functions directly. If C<Sub::Private> enforcement is added, a
  272: testing-interface export mechanism will be required.
  273: 
  274: =back

  281: 
  282:     mock('My::Module', 'method', sub { 'mocked' });

  300: warnings.

  511: =head2 after
  512: 
  513: Run a hook after a method and return the original's value.
